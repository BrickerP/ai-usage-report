# Round 6 — 安静的报表上下文

## 假设

当前最大的首屏噪声不是数据，而是“生成时间、时区、机器、全量时间跨度、口径说明、成本说明”同时展开。置信度：90%。

## 自问

这些信息应该删除、继续常驻，还是改成按需查看？

## 自答与选择

- 删除：最干净，但审计数据来源时会失去必要上下文。
- 继续常驻：信息完整，却让每天只想看趋势的人反复阅读同一段说明。
- 按需查看：首屏只保留更新时间和异常摘要，完整元信息、口径和成本说明进入明确的 disclosure。

选择按需查看。它是减法，同时不改变数据口径或可追溯性。

## 落地

- 页头只显示精简后的更新时间。
- 数据异常保留为可播报状态，但视觉文案缩短为“来源 + 状态 + 是否保留旧数据”。
- 新增带 `aria-expanded` / `aria-controls` 的 `Report details` 控件。
- 完整生成时间、时区、时间跨度、机器、来源状态、token 口径与成本说明保留在详情面板。

## 反思

“不常看”不等于“不重要”。将审计信息放入一层 disclosure，比用更小字号硬塞在页面上更可读，也比直接删除更可靠。
