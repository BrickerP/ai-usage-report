# Round 3 — 可操作的数据状态

## 自问

加载失败时应自动无限重试、展示诊断信息，还是给用户一个明确的重试动作？

## 自答与选择

- 自动无限重试：容易掩盖长期故障，也缺少停止点。
- 展示完整诊断：有助开发，但会泄漏实现细节并破坏页面语气。
- 明确重试：状态和下一步都可理解，行为也可控。

选择显式重试，并让 Loading、Error、Empty 都占据稳定、可识别的页面区域。

## 落地

- Loading 使用 `role="status"`、`aria-busy`、文字说明和受约束的进度提示。
- Error 使用 `role="alert"`，保留简洁错误信息和 Retry 按钮。
- 空时间线提供 Empty 文案及 Reload 操作，不再只留下空图。
- `prefers-reduced-motion` 下停止加载动画。

## 验证与反思

测试覆盖三类状态的语义和操作入口。状态不再只是“页面暂时少了一块”，而是明确回答发生了什么以及用户接下来能做什么。
