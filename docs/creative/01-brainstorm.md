# Explore 日柱状图：极值既是奖杯，也是可读分布

## Hypothesis

我对问题的理解置信度：**92%**。

这是一个个人 AI token 使用的裱花 / 历史成就系统，不是运营分析后台。7–20 的约 206 亿 tokens 应该成为访客第一眼看到的“奖杯”，但当前单一线性 y 轴把其它日期压成贴地线，时间分布失去叙事。

## 不是为谁

- 不是为财务或运营人员做精确的跨量级趋势预测。
- 不是要隐藏缓存流量、削平峰值或重新解释 token 口径。
- 是给本人和访问个人主页的人：先被峰值震住，再能看懂这段时间每天的使用节奏。

## How Might We

> **How might we 让 206 亿这一天保持“成就奖杯”的视觉重量，同时给普通日期一块诚实、线性的阅读空间，让访客既看到纪录，也读懂时间线？**

核心原则：**不改变数值，只重新分配图表像素；每个阅读层都保持线性，并把分界说清楚。**

## 发散的 8 个方向

| 方向 | 做法 | 优点 | 主要风险 |
| --- | --- | --- | --- |
| 1. 双线性 Spotlight Split | 同一张图拆成上下两个对齐的线性 band：下方读日常分布，上方读峰值奖杯；用连续连接线和明确的 axis break 表示同一根柱子的上下段 | 峰值不被弱化，普通天获得真实高度，时间顺序和原始数据保留 | 需要把两个 band 的关系解释清楚，避免被误读成两套数据 |
| 2. 主图 + Peak Inset | 主图保持日常线性尺度，右上/顶端放一个峰值日的完整线性 inset，峰值柱身用连接标记与主图对应 | 工程和响应式成本较低，峰值天然像奖杯卡片 | inset 容易像另一张图；峰值日期的时间位置需要额外提示 |
| 3. Magnitude Small Multiples | 按动态量级分成“日常层”和“纪录层”两个并列小图，每层各自线性，x 轴严格对齐 | 可读性强，适合展示“平时 vs 纪录” | 视觉分栏更重，Explore 区可能显得复杂 |
| 4. Peak Rail | 在主图顶部增加一条极值 rail，只画超过日常阈值的日期；主图保留完整日柱 | 极值可以做成很强的装饰性徽章 | rail 与主图的比例关系不够直觉，仍需解释阈值 |
| 5. Baseline Micro-bars | 保留原始图，再在底部增加一条固定高度的日常 micro-bar strip | 不动原图，普通天可读 | 形成重复图表，主路径变长；峰值污染仍存在于原图 |
| 6. 可切换“纪录 / 分布” | 默认 show-off 峰值视图，按钮切换到普通天线性视图 | 用户选择明确，交互简单 | 访客默认仍可能只看到被压扁的分布；核心问题被交给操作解决 |
| 7. 日历热力图 companion | 用日期热力图承担分布阅读，柱状图只承担峰值叙事 | 分布密度很强，适合长时间线 | 改变 Explore 的图表语义，不再是日柱状图 |
| 8. Capped bar + overflow label | 柱子在阈值处截帽，用“+18.6B”标出溢出 | 最省空间 | 直接截断感强，容易被理解为数据被隐藏；不符合“极值不能弱化”的约束 |

## 收敛后的 3 个候选

### A. 双线性 Spotlight Split（推荐）

- **用户价值**：同一眼看到“纪录有多夸张”和“其它日子如何分布”。
- **可行性**：沿用现有 ECharts；把一个 grid 拆成两个对齐 grid，仍使用原始 daily series 和 tooltip。
- **差异点**：不是 log/sqrt，也不是把峰值挤进卡片，而是把极值做成一个有明确断轴语法的奖杯层。
- **隐藏假设**：日数据能动态识别一组 peak day；移动端可以把两个 band 纵向堆叠而不破坏 Explore 区节奏。

### B. 主图 + Peak Inset

- **用户价值**：改动小，峰值可以拥有更强的标题、数字和光晕。
- **可行性**：可在现有图表旁边复用一个小型 ECharts 实例或同一 option 的第二 grid。
- **差异点**：更像“成就卡 + 时间线”，适合个人裱花叙事。
- **隐藏假设**：访客能理解 inset 与主图是同一天、同一份数据；否则会产生“重复统计”的疑问。

### C. Magnitude Small Multiples

- **用户价值**：阅读成本最低，两个线性坐标都能直接读数。
- **可行性**：实现稳定，但需要更明显的布局和标签改动。
- **差异点**：把“日常强度”和“历史纪录”变成两个并行章节。
- **隐藏假设**：Explore 区允许增加垂直高度；否则移动端会显得过长。

## 推荐选择与自问自答

**推荐 A，而不是先做切换按钮。**

自问：峰值会不会被拆开后反而不够震撼？
自答：不会。上 band 直接以纪录数字、峰值日期和高对比色做 hero；拆分的是坐标空间，不是成就本身。

自问：普通天是不是仍然被某个动态阈值“截掉”？
自答：下 band 只负责其线性域，上 band 负责所有超出段；每个超出日期都通过连接线、峰值标签和 tooltip 保留，不能静默丢失。

自问：这会不会变成专业报表、破坏 show-off 气质？
自答：不会。下 band 是时间线，顶 band 是奖杯台；用现有品牌色、数字标签和轻微 glow 表达成就，不增加新的业务卡片。

## 成功信号（进入设计前的验收目标）

1. 206 亿峰值在首屏仍是最大视觉焦点，峰值日期和完整数值无需 hover 就能读到。
2. 普通日期在默认视图中不再贴地；至少能看出高低层次和连续的时间节奏。
3. 两个 band 都标注线性单位和范围；axis break、连接关系、peak day 都有文字或 aria 说明。
4. 工具 / 模型筛选仍同时影响两个 band；tooltip 仍返回原始 token 值，不改变口径。
5. 移动端改为纵向双 band，不引入横向滚动；键盘和读屏用户能获得同一份“峰值 + 分布”的摘要。

## 需要在步骤 2 验证的假设

- 当前 `UsageCharts` 是否已经使用 ECharts 的多 grid / 多 yAxis 能力，还是单一 option。
- daily 数据是否有多个并列极值，以及工具 / 模型筛选后峰值是否会变化。
- 现有 tooltip、aria、响应式和测试是否允许双 band 而不破坏既有交互契约。

# 艺术重构 v2：Token Skyline / 纪录天际线

上一个版本虽然解决了坐标污染，但仍然像“两个报表拼在一起”。这个方向作废。新的中心不是 split axis，而是一个能被记住的个人成就意象。

## 新的视觉命题

> **把每天的 token 记录做成一条夜间天际线：普通日期是有灯光层次的城市街廓，最高纪录是穿出画布、带着金红 beacon 的纪录塔。**

这不是把数据画得更花，而是让图表拥有一个单一的故事：**我在这段时间里造出了一座自己的 token 城市。**

## 推荐构图：一条天际线，两个空间层

### 1. Ground：日常街廓

- 所有普通日期仍按原始值在线性尺度上绘制。
- 柱体不再是无差别矩形，而是窄幅“楼体 / 灯带”：保留现有堆叠色，顶部使用微弱的玻璃高光，底部接到同一条时间街道。
- 日期轴像街道编号，低对比；柱体高低是主要阅读内容。
- 这层的任务不是炫耀总量，而是让人读出“哪几天热、哪几天安静”。

### 2. Sky：纪录塔

- 极值日期的柱体从 Ground 继续向上，穿过一条被命名的 `RECORD HORIZON`，在 Sky 层完整抵达 206 亿。
- Horizon 不是普通折线，而是一条极细的金色“天际线 / 展柜边缘”，中间有一个断开折角，明确说明坐标层切换。
- 纪录塔使用唯一的高饱和 vermilion + champagne accent；顶端有小型 beacon / halo，数字 `20.6B` 和日期直接在塔顶旁展示。
- 如果筛选后出现多个并列峰值，它们成为同一组“纪录塔群”，而不是随机挑一个。

### 3. 连接语法

- Ground 中的峰值日期保留一个真实的塔基，Sky 中的上段使用同色半透明延伸；两段之间用一条极细的垂直光缆连接。
- 不允许使用“截断 + 省略号”。任何超出 Ground 的日期都必须在 Sky 层出现。
- 两层共享同一日期位置、同一 tooltip、同一筛选状态；这是一个作品，不是两张图。

## 艺术签名

- **签名元素**：`RECORD HORIZON` 天际线折角 + 纪录塔 beacon。
- **色彩角色**：obsidian 背景、slate-blue 日常楼体、vermilion 纪录塔、champagne 数字与天际线、低饱和 fog-blue 辅助线。
- **字体角色**：日期和正文使用现有无衬线；峰值数字使用现有数字 / mono 角色，形成“个人档案馆标签”而不是 SaaS 指标卡。
- **动效角色**：不让整张图持续闪烁；只让纪录塔的 beacon 在首次进入视口时完成一次呼吸亮起，避免炫技干扰读数。

## 为什么这次更像个人艺术品

1. 它有一个只有这个页面才有的隐喻：token skyline，而不是“异常值处理”。
2. 极值不是被容纳进一个小 inset，而是物理上突破图面，成为作品的构图中心。
3. 普通日期仍然是时间线，不会被装饰吞掉；艺术层叠加在数据之上，不替代数据。
4. 视觉层级来自空间、颜色和一个 beacon，不依赖更多卡片、按钮或解释文字。

## 自问自答

自问：如果普通柱子被做成楼体，会不会看不出仍然是柱状图？
自答：楼体只改变边缘、光泽和顶帽，不改变柱宽、基线、线性高度或 tooltip；第一眼仍是 bar chart，第二眼才读到城市隐喻。

自问：纪录塔穿出画布，会不会看起来像把峰值夸大？
自答：不会。Sky 仍是线性坐标，并在 Horizon 处明确标注范围；完整数值、原始 tooltip 和无障碍摘要共同提供校验。

自问：会不会为了艺术而增加太多视觉噪音？
自答：不会。只允许一个主签名元素（纪录塔 beacon）；普通柱体只获得轻微材质感，不加粒子、插画、纹理墙或新卡片。

## 当前选择

**选择 Token Skyline / 纪录天际线，放弃“两个报表面板”的表达。**

步骤 2 只需要验证三件事：现有数据是否能稳定识别 peak group、现有主题色能否支撑这组材质角色、以及 ECharts 的多 grid / custom series 是否能实现“连续塔基 + 天际线折角”而不破坏现有交互契约。
