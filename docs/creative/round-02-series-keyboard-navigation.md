# Round 2 — 模型序列键盘导航

## 自问

模型按钮应该维持逐个 Tab、增加左右方向键，还是增加搜索框？

## 自答与选择

- 逐个 Tab：实现最少，但 One API 模型较多时操作冗长。
- 搜索框：适合更高基数，但超出当前轻量报告的需要。
- 左右键 + Home / End：沿用工具栏类控件的熟悉键盘模式，且不增加视觉结构。

选择方向键方案，同时保留按钮原有的 Tab 可达性。

## 落地

- 序列组支持 `ArrowLeft`、`ArrowRight` 循环移动，以及 `Home`、`End` 跳转。
- 组内提供屏幕阅读器说明，按钮继续用 `aria-pressed` 表达 Focused 状态。
- 焦点只移动，不隐式改变选择；Enter / Space 仍负责触发。

## 验证与反思

纯函数测试覆盖循环、边界键、无效键与空列表。把“移动焦点”和“改变数据状态”分开后，键盘操作更可预测，也没有增加新的 UI。
