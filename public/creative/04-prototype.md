# THE ENDLESS BUILD — Pixel Night Run prototype

## Design contract

The report is BrickerP's living AI-builder save file: a restrained, Beijing-at-night pixel platformer built from real usage history. It borrows the spatial grammar of a 2D level—route, terrain, loadout, gate, checkpoint—but no characters, names, sprites, blocks, coins, pipes, sound, or trade dress from Super Mario or another game.

The gold command cursor `>` is the only player avatar. It connects code, AI work, and the idea of an endless build without inventing a mascot.

## Core journey

1. **Save cover** — `THE ENDLESS BUILD`, `SAVE FILE 001 · LIVE`, and one dynamic lifetime score: total recorded tokens. Cache-reused tokens and their ratio remain immediately visible, alongside the statement that usage is not output or productivity.
2. **World 01 / The Endless Run** — daily stacked usage becomes readable pixel terrain. On mobile it becomes explicitly labelled natural-week terrain. A true record day continues into the upper stage and receives a gold `RECORD` marker with its exact value.
3. **World 02 / Loadout Station** — Codex, Cursor, Claude Code, and One API remain the four truthful tools. Equipping one changes the chart and reveals its model gate.
4. **Model Gate** — opening a model list is inspection; Focus is a separate, persistent target lock. Focus updates the plotted emphasis, spend context, URL, visible state, and live accessibility announcement.
5. **Checkpoint Log** — highest day, recorded-day count, and tools used are derived from published data. No fictional XP, level, streak, achievement, or reward.
6. **Exact Ledger** — tooltips, token parts, model details, dates, and costs preserve exact report values for visitors who want the underlying record.

## Five observable states

| State | Visible response | Data and accessibility response |
| --- | --- | --- |
| All run | All tools ready; complete route | All-time is default; default URL omits range |
| Tool equipped | Selected loadout has a clear pressed/equipped state | Tool series and model gate update; URL gains tool |
| Models inspected | Model panel opens and receives focus | Region is labelled; Escape returns one layer |
| Target locked | Focused model is named beside the chart | Other model series dim; chart, spend, URL, and aria-live synchronize |
| Checkpoint viewed | Gold `RECORD` marker shows exact peak value | No log/sqrt transform, hidden total, or invented score |

## Visual system

- Night blue-black `#07131f`: world background.
- Road charcoal `#121c25`: platforms and panels.
- Moonlight ivory `#f1e8d2`: readable body copy.
- Sodium gold `#ffc84a`: player cursor, record, focus path.
- Hutong red `#d94a3d`: sparse landmark accents and errors.
- Focus teal `#55d6c2`: selected routes and accessible focus ring.

Pixel treatment belongs to silhouettes, borders, stamps, route marks, and display headings. Exact values and explanatory copy use a legible monospace face. The layout must never rely on pixel art alone to communicate selection.

## Responsive and state requirements

- Desktop uses daily terrain; mobile uses natural Monday-to-Sunday weekly totals and a vertical flow without horizontal dragging.
- Loading keeps a stable stage-shaped skeleton and a polite busy announcement.
- Error uses a broken-route save state, an assertive announcement, and a retry action.
- Selected controls expose `aria-pressed` or equivalent state; keyboard focus remains visible against every surface.
- `prefers-reduced-motion` removes smooth scrolling and chart/stage animation while preserving every final state.
- Visitor copy never exposes `RECORD SKY`, `RECORD HORIZON`, or `GROUND / TOKENS PER DAY`; implementation details may be explained only in an optional disclosure.

## Acceptance loop

`All time → Equip tool → View models → Focus model → Chart + URL + aria state change → Clear focus → Back to all tools`.

The feature is complete only when this loop works with mouse, keyboard, reduced motion, mobile layout, loading, and error states while all totals remain dynamically calculated.
